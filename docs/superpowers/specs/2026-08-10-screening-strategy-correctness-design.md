# 选股策略科学性与契约纠错设计

## 目标

在不引入新数据源、不改变 API、不过度拟合参数的前提下，修正内置选股策略中会造成误选、静默配置覆盖或能力宣传失真的确定性问题。第一阶段只保证策略名称、配置、可执行字段和测试契约一致，不宣称提升胜率。

## 范围

- 修改 `src/services/screening/strategies/*.yaml` 中直接参与全市场筛选的内置策略。
- 修改策略 YAML loader，拒绝重复键并校验可确定的跨字段约束。
- 补充针对策略加载和关键筛选语义的离线回归测试。
- 更新选股专题文档与 `[Unreleased]` changelog。
- 不修改 `strategies/*.yaml` Agent 分析策略草稿。
- 不修改组合管理、选股历史页面及其当前未提交改动。
- 不执行 Git commit、push、切分支或历史改写。

## 设计

### 1. 严格策略配置加载

策略 loader 在 YAML mapping 构造阶段检测重复键，发现重复键时抛出包含文件和键名的 `ValueError`，不再接受 PyYAML 的“后值覆盖前值”行为。保留现有未知字段校验。

增加最小跨字段校验：

- `*_min` 不得大于对应 `*_max`。
- `factor_weights` 不得包含负数，且至少有一个正权重。
- 内置策略显式提供 `factor_weights` 时不再保留无效的 `tech_weight`；loader 继续支持只使用 `tech_weight` 的旧自定义策略。

### 2. 龙头策略收敛为可执行能力

当前引擎没有连续涨停次数、封板时间、开板次数、封单金额和板块涨停梯队字段，因此 `dragon_board` 不再宣称能确定性识别首板、二板、炸板或龙头梯队。

策略调整为“强势题材候选（实验）”：

- 保留成交额、换手率、量比、强势涨幅、MA20、MACD、实体和题材热度条件。
- 删除重复的 `range_20d_pct_max`。
- 不再把 `range_20d_pct` 解释为阶段涨幅或连板高度。
- 使用真实的 `change_60d_max` 控制阶段过热。
- 增加前高附近/突破和 20 日量能确认，降低仅凭当日大涨入选的概率。
- 明确 9.95% 上限只适用于主板近涨停语义，因此不再把策略描述成覆盖所有 A 股涨停制度的打板策略。
- LLM 只负责核查题材与风险，不得声称已获得封板时间、连板或梯队数据。

### 3. 超跌反转必须使用日 K

`oversold_reversal` 增加日 K 硬条件，使 pipeline 自动进入日 K enrichment：

- 阶段收益为负，避免把单日回调误判为超跌。
- RSI 必须为 `oversold`。
- 限制波动率、ATR 和极端回撤，排除失控下跌。
- 要求最低日 K 数据质量，数据不足时不把缺失值当作有效反转信号。

策略仍定位为观察候选，不要求立即买入，也不将“低 PE/PB”当作止跌确认。

### 4. 价值类策略诚实命名

当前引擎的 `value` 仅由 PE/PB 构成，没有股息率、ROE、现金流、负债和盈利稳定性。因而：

- `quality_value` 改为“低估值稳健”，描述只覆盖估值、流动性和交易稳定性。
- `blue_chip_income` 改为“大盘低估值防守”，移除分红、现金流和收益质量承诺。
- ranking hints 可以要求 LLM 核查基本面，但不得把未结构化校验的内容描述为硬筛选事实。

### 5. 日 K 预选边界

本阶段不取消 `daily_enrich_max_candidates`，避免全市场逐股请求导致性能和限流问题。策略通过更宽但相关的快照过滤形成候选池，并在返回的 degradation 中保留实际 enrichment 覆盖率。完整召回率改造留到策略 T+N 评估阶段，用真实漏选数据决定预算，而不是直接扩大网络请求。

## 错误处理

- 内置或自定义策略出现重复键、非法区间或非法权重时，加载直接失败并指出文件与字段。
- 依赖日 K 的策略无法完成 enrichment 时保持现有 fail-fast 行为，不能静默退化为纯快照筛选。
- LLM 排序失败继续回退到确定性因子排序，不改变现有降级契约。

## 测试

- 重复 YAML 键被拒绝。
- 合法旧式 `tech_weight` 自定义策略继续可加载。
- 非法 min/max 与负权重被拒绝。
- 所有内置策略均可加载，factor weights 合法。
- `oversold_reversal` 被识别为需要日 K，且非超卖、阶段未下跌、极端波动样本被过滤。
- `dragon_board` 不含重复键，使用 `change_60d_max` 和可执行的突破/量能字段。
- 运行策略加载相关测试、内置 screening engine 测试和 Python syntax check。
