# 盘中市场监控与动态选股调度设计

## 目标

在现有盘中盯盘与通知链路上增加三类按北京时间墙钟触发的任务：

- 10:00、14:00 根据大盘状态动态执行选股并推送前 5 只候选。
- A 股交易时段每 10 分钟采样大盘指数，识别明显持续上涨或下跌。
- 个股盯盘固定在上午 `09:30` 至 `11:30`、下午 `13:30` 至 `15:00` 的整点/半点运行，不再按上次完成时间顺延。

## 调度边界

盘中任务统一使用 `Asia/Shanghai` 墙钟时间，并由现有盘中常驻进程负责。服务重启后计算下一个尚未经过的时间槽，不按重启时刻重新累计间隔。

个股盯盘时间槽：

```text
09:30 10:00 10:30 11:00 11:30
13:30 14:00 14:30 15:00
```

大盘采样在 A 股交易阶段每 10 分钟运行。午休、盘后、周末和节假日跳过；午后开始时清除午休前用于短周期趋势判定的样本，避免把跨午休变化当成连续趋势。

每类任务按“交易日 + 时间槽 + 任务名”去重。任务错过时间槽后不追补；同类任务尚在执行时不并发启动下一份。

## 大盘持续趋势判定

采集上证指数、深证成指、创业板指的实时点位。保留同一交易时段最近 3 个有效样本，覆盖约 20 分钟。

判定规则：

- 至少 2 个指数在两个相邻区间中连续同方向变化。
- 三个指数从首样本到末样本的累计涨跌幅中位数绝对值至少为 `0.35%`。
- 满足上涨条件为 `sustained_up`，满足下跌条件为 `sustained_down`，否则为 `neutral`。
- 数据不足或少于 2 个指数有效时保持 `neutral`，不根据不完整数据发出趋势告警。

通知只在状态转换时发送：进入持续上涨、进入持续下跌，以及从持续状态恢复为中性。连续保持相同状态不重复推送。

## 动态选股

每天在 `10:00`、`14:00` 读取最新大盘状态并选择策略：

```text
sustained_up   -> dragon_board
sustained_down -> low_volatility_quality
neutral        -> shrink_pullback
```

每次最多输出 5 只候选，通过现有 `alert` 通知路由发送。推送包含执行时间、大盘状态、策略选择原因、候选代码/名称/分数/风险，以及数据源或 LLM 降级摘要。没有候选时也发送成功执行但无候选的结果。

选股任务与个股盯盘在同一时间槽相遇时，先完成大盘采样与状态更新，再启动选股，最后运行个股盯盘。选股失败只记录并推送简短失败信息，不终止盘中调度进程。

## 配置与兼容

新增配置默认关闭，避免升级后意外增加网络请求或通知：

```dotenv
INTRADAY_MARKET_MONITOR_ENABLED=false
INTRADAY_MARKET_MONITOR_INTERVAL_MINUTES=10
INTRADAY_MARKET_TREND_THRESHOLD_PCT=0.35
INTRADAY_SCREENING_ENABLED=false
INTRADAY_SCREENING_TIMES=10:00,14:00
INTRADAY_SCREENING_MAX_RESULTS=5
```

现有 `INTRADAY_WATCH_INTERVAL_MINUTES=30` 保留作为兼容配置，但执行语义改为墙钟对齐；下午开始时间固定为 13:30。关闭新开关时，现有普通分析、Web 选股和通知行为不变。

## 验证

- 单元测试覆盖时间槽计算、午休/下午起点、服务重启不漂移和时间槽去重。
- 单元测试覆盖三指数上涨、下跌、阈值不足、数据不足和恢复中性。
- 单元测试覆盖三种市场状态到策略的映射、10:00/14:00触发和空候选推送。
- 回归测试覆盖现有盘中盯盘格式、通知路由和调度模式注册。
- 运行 Python 编译检查和相关 pytest；不执行 Git 提交或推送。

## 回滚

将 `INTRADAY_MARKET_MONITOR_ENABLED=false`、`INTRADAY_SCREENING_ENABLED=false` 后重启盘中服务，可关闭新增能力。代码回滚只涉及盘中调度、配置、测试和文档，不修改持仓或选股历史数据。
