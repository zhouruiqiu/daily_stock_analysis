# 盘中持仓跌破支撑高亮提醒设计

## 目标

在现有盘中自选盯盘推送内，对实时价跌破最近有效支撑位的真实持仓增加高亮风险提醒。不新增独立消息，不改变现有调度频率，不调用 LLM。

## 判定规则

1. 仅对 `quantity > 0` 的真实持仓判断；未持仓自选股不高亮。
2. 只使用实时行情中的有效现价触发；实时行情缺失时不用日 K 收盘价代替。
3. 从技术分析结果的前两个正数支撑位中，取最高值作为“最近支撑位”。
4. `realtime_price < nearest_support` 时判定为跌破。
5. 跌破幅度按 `(nearest_support - realtime_price) / nearest_support * 100` 计算并保留两位小数。
6. 每次原盯盘推送都重新判断；仍低于支撑时持续高亮，重新站上后自动取消。

## 数据结构

在 `IntradayPositionScore` 中追加三个兼容字段：

- `nearest_support: Optional[float]`
- `support_breached: bool`
- `support_break_pct: Optional[float]`

旧调用方不传递或不使用新字段时保持原行为。原有综合评分和防守位计算保留，将“现价跌破成本防守位”修正为更准确的“现价跌破防守位”。

## 推送展示

格式化前先将 `support_breached=true` 的持仓稳定排到列表前面，其余股票保持原顺序。跌破股票的区块使用：

```text
🚨【跌破支撑】招商银行 600036
⚠️ 现价 39.80 < 最近支撑 40.20（跌破 1.00%）
综合评分 42/100 · 持仓 · 考虑减仓 · 风险高
```

原有成本、浮盈亏、防守位、均线、MACD、量比和支撑压力内容继续展示。

## 异常与边界

- 持仓读取失败：沿用现有自选技术观察降级，不显示持仓跌破提醒。
- 实时价或支撑位缺失、非数值、非正数：不触发高亮，其他分析继续。
- 价格等于支撑位：不视为跌破。
- 单只股判定失败：沿用现有失败隔离，不中断整份推送。

## 验证

增加确定性单元测试，覆盖：

- 持仓实时价跌破最近支撑时输出结构化跌破信息。
- 未持仓自选股不高亮。
- 实时行情缺失时不误报。
- 价格重新站上支撑后不高亮。
- 跌破持仓置顶，未跌破股票保持原顺序。
- 企微推送仍只调用原 `alert` 路由一次。

## 发布与回滚

只需发布盘中持仓评分器和盯盘 Worker 相关文件，重启 `dsa-intraday-watch`。发布前对远程文件做时间戳备份；回滚时恢复备份文件并重启该服务。
